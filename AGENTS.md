# Правила репозитория

## Закрытый архив

- Прежние процессорные опыты целиком находятся в `archive/processor-experiments/`; пути `rtl/`, `constraints/`, `tb/`, `scripts/` в их документации относятся к этому каталогу.
- Архив завершён и исключён из новой разработки. Не изменять и не подключать его к новой задаче без отдельного запроса пользователя.
- Ветка архива — `archive/processor-experiments`. Не сливать её в `main`.

## Язык проекта

- Общение с пользователем, документация, журналы, комментарии и новые имена пользовательских команд должны быть на русском языке.
- Не использовать англицизмы, если есть точный и естественный русский эквивалент.
- Английские термины допустимы для имён программ, стандартов, интерфейсов, файлов, команд и идентификаторов в исходном коде, а также когда перевод создаёт неоднозначность.
- При первом употреблении редкого английского термина кратко пояснить его по-русски.

## Источник истины

- RTL находится в `rtl/`, ограничения выводов — в `constraints/`, испытательные модули — в `tb/`, сценарии сборки — в `scripts/`.
- Проекты Vivado, `build/` и `reports/` создаются автоматически. Не считать их исходниками, не править и не сохранять в Git.
- Целевой кристалл — `xc7z020clg400-1`, пока измерения или документация платы не докажут иное.
- Долговременные решения записывать в `docs/05 Журнал решений.md`, работу с платой — в `docs/07 Журнал работ.md`.

## Порядок работы

- Перед изменениями, затрагивающими плату, прочитать `docs/03 Аппаратная часть.md`.
- После изменения среды выполнить `make doctor`.
- Для изменений RTL выполнить `make lint` и `make sim`; при наличии Vivado выполнить `make synth`.
- Предпочитать автоматизацию через командную строку и Tcl. Графическая оболочка Vivado служит для просмотра и отладки, но не для хранения исходного проекта.

## Безопасность оборудования

- Разрешены чтение сведений отладчика и обнаружение цепочки JTAG без изменения состояния.
- Не останавливать и не сбрасывать процессоры, не писать в память, PL, QSPI, SD или eFUSE без явного разрешения пользователя.
- Не убирать предохранитель `ALLOW_FPGA_PROGRAM=YES` из `make program`.
- Не придумывать назначения выводов. Для каждого ограничения указывать схему или руководство и состояние проверки на плате.

## Работа с Git

- Сохранять посторонние изменения пользователя. Один коммит должен решать одну задачу; заголовок — в повелительном наклонении.
- Не сохранять в Git секреты, местные пути, созданное Vivado состояние, файлы прошивки, контрольные точки и отчёты.
