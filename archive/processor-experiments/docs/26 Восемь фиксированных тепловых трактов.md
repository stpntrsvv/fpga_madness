# Восемь фиксированных тепловых трактов

Дата: 2026-10-21. Продолжение [опыта FCLK на четырёх трактах](25%20Фиксированная%20сетка%20от%20FCLK.md). Задача — увеличить пропускную способность фиксированного теплового решателя, сохранив поля, карты и арифметику обычного C/NEON. Загружаемый граф не добавляется.

## Аппаратный результат

Полный набор на реальном XC7Z020 прошёл: **14764 пакета**, полные поля, ошибки арифметики и общая отмена шага совпали с эталоном. Для 64 шагов поля 64×64, dt_raw=4096, получены **34240 тактов**, **535 тактов/шаг**.

| Реализация | Время шага |
| --- | --- |
| Скалярный C, одна нить M1, исходная серия 21 октября | 24.211 мкс |
| NEON, одна нить M1, исходная серия 21 октября | **8.393 мкс** |
| Реальная FPGA, восемь трактов, CFGMCLK | **8.303 мкс** |
| NEON, дополнительный повтор после контрольных чтений | 9.263 мкс |

Для основного сравнения взята наиболее быстрая измеренная серия CPU. FPGA дала время на **1.07% меньше**, то есть практически паритет с одной нитью M1. Относительно четырёх трактов на FCLK100 из документа 25 время сократилось примерно в **1.26 раза**; это разные аппаратные режимы и отдельные CPU-серии. Сравнение с несколькими ядрами M1 и измерение энергии не выполнены.

Частота перед полным набором: **64.302–64.565 МГц**, середина **64.433268**; после: **64.360–64.617 МГц**, середина **64.488425**. Интервалы перекрываются. Расчёт времени использует середину перед опытом. Если взять крайние границы обоих интервалов, время шага находится примерно в **8.280–8.320 мкс**. Это неопределённость оценки частоты по счётчику и времени обмена, а не измерение всех источников погрешности. Полезная скорость в основном расчёте — около **493 млн обновлений состояния в секунду**.

Состояния и карты остаются в PL между шагами. Загрузка образа, массивов и чтение результата через JTAG исключены; у CPU исключены выделение, подготовка, копирование начального поля и контрольная сумма. Это время вычисления уже подготовленной задачи. Такты M1 не измерялись.

После полного набора выполнен CLEAR. Отдельным чтением подтверждены GRD1, число трактов 8, busy=0, done=0, fault=0, нулевые счётчики и dt. Признаки загруженности сняты, BRAM побитно не очищалась. Повторное чтение PS подтвердило только разрешённое изменение devcfg.CTRL[30]; прочие проверяемые регистры PLL, тактов, сбросов и преобразователей уровня совпали. DEVCFG_STATUS изменился в соответствии с состоянием PL.

Основной отчёт: `reports/сетка-плата-8-2026-10-21.json`; пакеты: `reports/сетка-плата-8-2026-10-21.log`; сводка с контрольными суммами: `reports/итог-сетки8-2026-10-21.json`. Итоговое состояние: `reports/сетка8-итоговое-состояние-2026-10-21.log`. Файлы создаются автоматически и не сохраняются в Git.

Отдельное последующее [сравнение со STM32N6](27%20Тепловая%20сетка%20на%20STM32N6.md) выполнило скалярный C и Helium с прямой настройкой CMSIS, без HAL. Его результаты сохранены отдельно; исходная база FPGA/M1 выше не заменяется.

## Устройство

`grid_core` получает параметр LANES со значениями 4 и 8. По умолчанию остаются четыре тракта; программируемый профиль допускает только четыре. Для восьми используются отдельные оболочки `grid8_core`, `grid8_top` и `grid_fclk8_top`. Размер поля по-прежнему 64×64; две температуры и четыре карты остаются в памяти PL. Каждому из восьми трактов соответствует банк из 512 слов на каждом массиве. Потоки между соседями передаются локально, южные потоки хранятся в строковой памяти. Между группами переносится только крайний восточный поток.

В каждом тракте четыре полных произведения 32×32; всего **128 DSP**, вместо 64. Разбиение памяти увеличивает физический расход блоков: число хранимых состояний само по себе не определяет стоимость памяти с нужным числом одновременных обращений.

Q16.16, округление вниз, порядок проверяемых операций и общая отмена ошибочного шага сохранены. Пробный снимок становится текущим только после завершения всего поля без ошибки. Ширина пакета управления не меняется. Регистр 18 сообщает число трактов; версия GRD1 и остальные адреса сохранены.

## Проверки до платы

Прошли `make doctor` (Vivado не настроен), `make lint`, lint восьмитрактного профиля и `make sim`. Восьмитрактный RTL прошёл **14728 проверок** и 12 пакетов транспорта. Отдельные проверки порядка результатов контролируют все восемь трактов и отсутствие пропущенных или повторённых групп. Четырёхтрактный контроль прошёл прежние **14727 проверок**, общий контроллер программируемого профиля — **18241**, по 12 пакетов транспорта.

Полные поля сравниваются с независимым Python-эталоном, включая 64 шага исходного поля CPU-опыта, нестепенной dt, знаковые данные, переполнения, отказ последней точки и сохранение ранее принятых шагов. Подтверждено **535 тактов на шаг**: 512 групп и 23 такта заполнения/завершения. Это число также подтверждено аппаратным счётчиком.

Сборка `grid-fclk8` проверяет известное ограничение упаковщика nextpnr 68aeeb3: 128 независимых DSP требуют обоих мест в плитке. Применяется существующая строгая проверка режима DSP и снятие только принудительной привязки Z=6, с сохранением исходной схемы. Проверки маршрутов данных и управляющих признаков FASM обязательны.

Схема восьмитрактного ядра после синтеза FCLK-варианта прошла 14728 проверок и 12 пакетов транспорта. Для RAMB18E1 добавлена ограниченная модель SDP 512×36, READ_FIRST с общей тактовой сетью и записью B; другие режимы отвергаются. Соответствие портов проверено по [AMD UG473, таблица 1-15](https://docs.amd.com/api/khub/documents/9gZGbqBxtlKXxBfkBt~lAg/content).

Синтез FCLK-варианта: 11370 LUT (без 32 RAM32M), 37830 регистров, 128 DSP, 96 RAMB18E1 и PS7. Каждое описание банка получило две копии SDP для двух чтений; это 48 эквивалентов BRAM36, а не 24. Трассировка FCLK-варианта остановлена после размещения, когда чтение PS выявило недоступность прежнего источника. Результат по частоте этой попытки не заявляется. Первая сборка `grid8-safe` от внутреннего CFGMCLK дала 74.05 МГц и отказала при требовании 80 МГц. Повторная сборка с явно выбранным ограничением **70 МГц** завершилась с оценкой **74.05 МГц**; JTAG 84.50 МГц при требовании 1 МГц. Все ограничения выполнены. Изменение ограничения не меняет частоту генератора.

Проверены 128 DSP, 5504 входа данных и 1280 корректирующих признаков FASM. Схема внутреннего варианта после синтеза также прошла 14728 проверок и 12 пакетов транспорта. Ресурсы: **11349 логических LUT, 37830 регистров, 128 DSP, 96 RAMB18E1, 32 RAM32M**, один STARTUPE2. SHA256 образа `a7815191f5db826047ae2fd40fe17ed02336791155960238a0a778f751389bfa`. После разрешённого снятия удержания PL образ передан через OpenOCD и завершил запуск: STAT=0x46107FFC. Подтверждены GRD1, восемь трактов и полный аппаратный набор, описанный выше. Условные 5.35 мкс при 100 МГц не являются измерением платы.

## Свежий обычный C/NEON

После завершения собственных тяжёлых задач и остановки ожидающего загрузчика заново выполнен прежний CPU-сценарий. Прошли 460 обычных и 460 сравнений с UBSan. Для 64×64, dt_raw=4096, 64 шага: скалярный C 24.211 мкс/шаг; NEON **8.393 мкс/шаг**. Это одна нить M1, прежние массивы, арифметика и проверенная явная векторизация. Отчёт: `reports/сравнение-сетки8-2026-10-21.json`. Его модельные столбцы не являются результатом восьмитрактного RTL.

Условная частота равенства восьми трактов при 535 тактах — **63.745 МГц**. Измеренный генератор немного выше этой границы; большого запаса по скорости пока нет.

Дополнительные повторы сохраняются полностью. Первый запуск рядом с контрольными чтениями PS/ядра дал медиану **10.272 мкс**, отдельный повтор после завершения этих чтений — **9.263 мкс**; во втором девять выборок лежали между 8.806 и 11.827 мкс. В исходной быстрой серии — между 8.359 и 8.429 мкс. Привязки к определённому ядру и фиксации частоты M1 нет, поэтому точная причина межсерийной разницы не установлена. Эти результаты показывают, что запас около 1% недостаточен для заявления об устойчивом превосходстве на любом запуске.

Повторы используют тот же исполняемый файл, `example(64,64)`, dt_raw=4096, 64 шага и прежний `run_c`; сверены исходные и конечные поля. Девять серий и прогрев сохранены. Отчёты: `reports/сетка8-CPU-повтор-2026-10-21.json` и `reports/сетка8-CPU-повтор-без-обмена-2026-10-21.json`; использованные сценарии сохранены рядом. Самая быстрая исходная серия не заменяется более медленной при расчёте отношения.

## Следующая экономия памяти

У массивов карт второй порт чтения не используется решателем, но общий модуль `grid_memory` пока синтезируется с двумя портами для каждого массива. Следующий отдельный кандидат — явно выключить второй порт у четырёх карт. Для восьми банков структурная оценка снижения — с 96 до 64 RAMB18: 32 блока для двух температур с двумя чтениями и 32 для четырёх карт с одним. Это оценка будущей правки; текущая сборка использует 96. Её не следует смешивать с аппаратным сравнением числа трактов.

## Состояние тактирования платы

21 октября JTAG, BYPASS и повторное чтение IDCODE исправны. После перерыва настройки PS отличаются от опыта 20 октября: IO_PLL_CTRL=0x0001A008, FPGA0_CLK_CTRL=0x00101800, LVL_SHFTR_EN=0, FPGA_RST_CTRL=0x01F33F0F. Сценарий проверки FCLK отверг этот режим: PLL в обходе, преобразователи PS/PL выключены. Вчерашние 100 МГц не предполагаются сохранёнными. На этом этапе выполнялось только чтение. Позднее для загрузки потребовалось отдельно разрешённое снятие удержания PL, описанное ниже.

Перед аппаратным опытом нужен проверенный доступный источник. Вариант от внутреннего генератора собран и прошёл свои временные ограничения; перенастройка тактов PS ему не требуется. Любые записи PS требуют подготовленного конкретного изменения и разрешения по AGENTS.md.

### Причина остановки загрузки

openFPGALoader оставался в `Xilinx::program_mem → Jtag::shiftIR`, ожидая INIT_B; это установлено по выборке стека процесса, а не по одному отсутствию вывода. В [исходнике загрузчика](https://github.com/trabucayre/openFPGALoader/blob/master/src/xilinx.cpp) этот цикл не ограничен временем. Процесс остановлен; последующее чтение STAT дало 0. Исходное объяснение ожидания медленной передачей было неверным: образ ещё не передавался.

Чтение MEM-AP: DEVCFG_CTRL=0x0E00E07F, DEVCFG_STATUS=0x40000A00, DEVCFG_MCTRL=0x30800100. PL имеет питание (MCTRL[8]=1), но PCFG_PROG_B=0 удерживает её в сбросе. Назначение бита подтверждено [AMD UG585, devcfg.CTRL](https://docs.amd.com/r/en-US/ug585-zynq-7000-SoC-TRM/Register-XDCFG_CTRL_OFFSET-Details).

Подготовлен `scripts/ps_pl_release.py`: по умолчанию только печатает план. Отдельно разрешённый режим с ALLOW_PS_PL_RELEASE=YES выполняет **одну запись** devcfg.CTRL по адресу 0xF8007000: 0x0E00E07F → 0x4E00E07F. Меняется только PCFG_PROG_B, затем проверяются значение и подъём INIT_B с ограниченным ожиданием. Предварительно проверяются исходное значение и питание PL. PLL, такты, процессоры и память не настраиваются. Пользователь явно разрешил эту запись. Она выполнена: CTRL=0x4E00E07F, STATUS=0x40000A30, INIT_B поднялся. Других записей PS не выполнялось. Перед восьмитрактной загрузкой добавлена отдельная проверка `--проверить-готовность`, которая только читает питание, PCFG_PROG_B и INIT_B. До снятия удержания она правильно отказала; после разрешённой записи проверка прошла. Журнал: `reports/сетка8-снятие-удержания-PL-2026-10-21.log`.

Сырые чтения и план: `reports/сетка8-PS-и-DEVCFG-2026-10-21.json`, `reports/сетка8-план-снятия-удержания-PL-2026-10-21.txt`, `reports/сетка8-конфигурация-после-ожидания-2026-10-21.log`.

### Передача образа и завершение запуска

Первая полная передача через openFPGALoader на 1 МГц дала INIT=1 и отсутствие ошибок CRC/ID, но STAT=0x46001F0C: DONE/EOS/GWE не поднялись. Дополнительные JSTART, CMD START и проверенный выбор TCK в COR0 для последовательности запуска не помогли. Рабочий такт вычислителя при этом не менялся. Эти попытки не считаются успешным аппаратным запуском.

Повторная передача **того же образа** через штатный драйвер Zynq в OpenOCD на 1 МГц заняла 171 секунду и дала STAT=0x46107FFC. Передача заново восстановила исходные конфигурационные регистры образа; дополнительных записей PS не выполнялось. Точная причина различия двух процедур пока не установлена. Команда `программировать-сетку8` теперь выбирает OpenOCD по умолчанию; явный FPGA_PROGRAMMER может выбрать другой загрузчик, но независимая проверка STAT остаётся обязательной.

Журналы: `reports/сетка8-загрузка-после-разрешения-2026-10-21.log`, `reports/сетка8-загрузка-OpenOCD-2026-10-21.log`, `reports/сетка8-первый-ответ-2026-10-21.log`. Восьмитрактное измерение частоты использует паузу 10 секунд для уменьшения относительной неопределённости обмена; старый четырёхтрактный сценарий сохраняет две секунды.

## Воспроизведение

```sh
make lint
make sim
GRID_LANES=8 sh scripts/sim_grid.sh
sh scripts/sim_grid.sh
make сетка8
GRID_LANES=8 sh scripts/sim_grid.sh --после-синтеза grid8-safe
```

Для внутреннего генератора после успешной сборки: `ALLOW_FPGA_PROGRAM=YES make программировать-сетку8`, затем `make сравнить-сетку8`.

Для FCLK аппаратная проверка возможна лишь после успешной проверки источника: `scripts/ps_clock.py --проверить-образ build/сетка-fclk8.bit`. Команды программирования сохраняют ALLOW_FPGA_PROGRAM=YES и проверку свидетельства. Для полного сравнения уже настроенного FCLK-варианта: `make сравнить-сетку-fclk8`.
