## Два разных вида параллелизма

### Одна большая связанная система

Пример — тепловая сетка из сотен состояний. Потоки тепла на разных рёбрах сетки могут вычисляться одновременно по состоянию одной эпохи. Пространственные узлы полезны, когда одновременно готово много независимых взаимодействий.

Большой граф не обязательно широкий: длинная последовательная цепь из ста узлов всё равно требует ожидания зависимостей. Здесь важны ширина готовой работы и глубина пути, который определяет готовность шага. Обмен между соседними областями и общий переход состояний остаются частью одной физической модели.

Нынешнее ядро вмещает четыре состояния и девять узлов. Пример большой сетки объясняет направление исследования; текущий RTL такую сетку ещё не исполняет. Увеличивать полную сеть выбора источников до сотен узлов без оценки ресурсов нельзя.

### Несколько независимых систем

Пример — сто одинаковых двигателей с разными начальными условиями или параметрами. У каждого экземпляра собственные состояния, номер шага и ошибки; зависимости между двигателями отсутствуют.

Наш умножитель принимает новые операнды на каждом такте, хотя результат проходит четыре стадии. Если считать одну траекторию и ждать её результата, приём новых значений используется редко. Независимые траектории позволяют подать A на первом такте, B на втором, C на третьем, D на четвёртом, пока прежние данные продолжают движение по стадиям.

Это требует банков состояний, указания владельца каждого результата, учёта готовности отдельно по экземплярам и отдельного согласованного принятия их шагов. Общая ошибка одной траектории не должна отменять шаг остальных. Простого изменения `state_count` для этого недостаточно. Несколько экземпляров, чередуемых внутри одного набора узлов, пока не реализованы.

При общем графе узлы сохраняют свои операции и связи, а между экземплярами переключаются наборы состояний и параметров. Центральная выборка арифметических команд для этого не требуется. Возможность одновременно держать разные графы потребовала бы отдельной оценки цены конфигурации и коммутации.

## Задержка и пропускная способность

| Вопрос | Что измеряем |
| --- | --- |
| Как быстро один двигатель получит своё следующее состояние? | Задержку шага одной траектории |
| Сколько шагов всех двигателей выполнено за секунду? | Суммарную пропускную способность |

Заполнение стадий несколькими экземплярами может повысить пропускную способность, не уменьшая задержку одного экземпляра. Для управления единственным двигателем это не гарантирует пользы. Для перебора параметров, ансамблей и множества объектов такое улучшение может быть полезно.

На CPU независимые траектории тоже следует раскладывать по компонентам и обрабатывать векторными командами SIMD: одна команда выполняет однотипную операцию над несколькими значениями. Необходимо сохранить одинаковые округления, отказ шага и ошибки отдельно по траекториям. Для многопоточного сравнения отдельно указывается число потоков; одиночный последовательный C остаётся базой только для задержки одной траектории.

Новых измерений ансамблей и большой системы пока нет. Их преимущество не выводится из частоты или числа DSP.

## Текущий опыт сокращения задержки

При положительном `dt_raw = 2^p`, `p = 0…30`, точное произведение можно получить знаковым расширением производной до 64 бит и сдвигом влево на p. Следующий знаковый сдвиг на 16 сохраняет округление вниз Q16.16. Большие показатели могут переполнить конечное состояние; проверка и общая отмена шага обязательны.

В RTL признак степени и показатель регистрируются до запуска. Для прочих положительных dt остаётся полный тракт DSP. Это выбор по параметру загруженной модели в одном и том же оборудовании. Шаг Эйлера и численная точность сохраняются.

Простые узлы были проверены в варианте с одной стадией. Первый вариант с прежним двоичным выбором источников прошёл RTL, но дал лишь 54.77 МГц при требовании 80 МГц. Он не выдан для программирования. Ограничивающий путь проходил от кода источника через выбор операнда и арифметику; 15.5 нс из 18.3 нс приходились на соединения.

Второй вариант заранее раскрывал коды источников в зарегистрированные отдельные признаки выбора. Он тоже прошёл RTL, но дал 63.98 МГц; 12.9 нс из 15.6 нс критического пути приходились на соединения. Оба однотактных варианта отклонены. Для текущего опыта возвращены две стадии простых узлов и прежняя сеть выбора источников, быстрый интегратор проверяется отдельно.

В моделировании получено 12 / 17 / 12 / 5 тактов для Лоренца, RLC, тепла и осциллятора соответственно. Для произвольного положительного dt, не равного степени двойки, сохраняются шесть тактов интегрирования. Изменение числа стадий принимается по времени шага и выполнению ограничений, а не только по успеху RTL.

В промежуточном варианте с двумя стадиями узлов двоичный выбор производной дал 71.12 МГц. Раскрытие только четырёх источников производных повысило оценку до 75.37 МГц; ограничение 80 МГц всё ещё не выполнено. Следующий выявленный путь заканчивался в отладочном чтении: выбор продукта, сумма, общая проверка переполнений и выбор адреса. Диагностический признак переполнения отделён регистром; его чтение запаздывает на один такт относительно вычислительного тракта, принятие шага не задерживается.

Промежуточный отдельный диагностический регистр дал 79.14 МГц, тоже ниже требования. В окончательном устройстве признаки переполнения пробного перехода сохраняются отдельно для каждого состояния одновременно с его пробным значением. COMMIT объединяет уже сохранённые признаки. Диагностика использует эти же регистры: бит 12 адреса `0x0004` теперь означает переполнение последнего проверенного перехода, а не непрерывную проверку комбинационных сигналов. CLEAR очищает признаки; чтение не удлиняет арифметический путь. Число тактов шага не увеличивается.

## Равные условия для C

Генератор C тоже получает быстрые пути для степеней двойки. Выбор общего произведения, правого сдвига или левого масштабирования происходит до цикла шагов. Округление отрицательных значений задано переносимыми выражениями; знаковый сдвиг влево отрицательного числа не используется.

Проверяются все 31 положительная степень и соседние значения dt, которые должны выбирать общий путь, а также прежние случайные данные и переполнения. Обновлённая база сравнения прошла 720 случаев: 360 с обнаружением неопределённого поведения и 360 в оптимизированной сборке. Исторические измерения C без этих путей сохраняются отдельно.

Это функциональные проверки схемы; загрузка и измерение полной новой конфигурации ожидают возвращения платы.
