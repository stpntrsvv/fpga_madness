# FPGA Madness

Исследование процессора динамических систем на QMTECH ZYNQ7000 Bajie Board (`XC7Z020-1CLG400C`). Ядро хранит состояния и исполняет загружаемый граф производных: одна конфигурация FPGA для разных моделей, без центральной выборки арифметических команд.

Малый программируемый профиль — [второе ядро](docs/14%20Второе%20ядро.md): 4 состояния, 8 параметров, 9 пространственных узлов, Q16.16 и явный Эйлер; независимый генератор, передача между тактовыми областями с подтверждением, умножение со стадиями на DSP48E1. JTAG через DAPLink остаётся интерфейсом управления. Полное ядро проверено на плате 2026-10-18; измеренная частота около 64.85 МГц. Подробности: [аппаратный опыт](docs/18%20Аппаратный%20опыт%20автономного%20ядра.md).

Текущая [версия с быстрым интегратором](docs/15%20Задержка%20шага%20и%20параллельные%20системы.md) сокращает шаги четырёх моделей с 15 / 20 / 15 / 8 до 12 / 17 / 12 / 5 тактов. После исправления пропущенного маршрута данных DSP ограничение сборки 80 МГц выполнено; оценка nextpnr 87.28 МГц, 10555 LUT и 52 DSP. Оценка частоты не является аппаратным измерением. C получил такие же быстрые пути для dt.

RTL и схема после синтеза прошли 494 обмена, 64 перехода интегратора и 3 отказа dt, 448 произведений и 49 проверок передачи между тактовыми областями. На плате прошли 494 проверки, 72 полных произведения четырёх интеграторов и миллион автономных шагов без TCK. C прошёл 720 случаев. На четырёх малых моделях FPGA получает 77–262 нс/шаг, C на одном потоке M1 — 1.18–7.50 нс/шаг; M1 быстрее примерно в 25–65 раз без учёта JTAG.

Исторический первый профиль без DSP и с тактированием от TCK 1 МГц выполнил четыре модели на плате побитово правильно. В первом сравнении одной траектории оптимизированный C на одном потоке Apple M1 получил 3.72–10.47 нс/шаг; тот профиль FPGA — 3000–6000 нс/шаг без пауз USB. Эти результаты относятся к первому ядру.

Начало: [документация](docs/00%20Начало.md), [архитектура](docs/09%20Архитектура%20машины%20состояний.md), [первое ядро и протокол](docs/11%20Первое%20ядро.md).

Большой кандидат: [потактовая модель сетки 128×128](docs/20%20Потактовая%20модель%20большой%20сетки.md). Команды `make проверить-модель-сетки` и `make модель-сетки` работают без платы; результаты 128×128 остаются программным прогнозом. Отдельный [RTL-опыт 64×64](docs/22%20Аппаратная%20тепловая%20сетка%2064×64.md) содержит четыре тракта фиксированного теплового закона, BRAM и пакетный JTAG: `make проверить-сетку`, `make сетка`.

На плате тепловой профиль прошёл 14763 пакета и дополнительную проверку обоих снимков. 64 шага заняли 67008 тактов: **16.18 мкс/шаг** при измеренных 64.718 МГц, против **8.73 мкс** одного потока M1 с NEON. FPGA медленнее в **1.85 раза**. Ресурсы: 7990 LUT, 24589 регистров, 64 DSP, 24 BRAM36; оценка трассировки 88.76 МГц, цель 125 не выполнена. Это исторический опыт от 2026-10-18; последующие результаты приведены ниже. Малые программы DPU2 несовместимы с GRD1.

[Опыт FCLK0 100 МГц](docs/25%20Фиксированная%20сетка%20от%20FCLK.md) от 2026-10-20: полный аппаратный набор прошёл, **10.468 мкс/шаг против свежих 8.710 мкс NEON**, четыре тракта.

[Восемь реальных фиксированных трактов](docs/26%20Восемь%20фиксированных%20тепловых%20трактов.md), 2026-10-21: **535 тактов и 8.303 мкс/шаг** против наиболее быстрой свежей серии **8.393 мкс NEON** одной нити M1. Полный аппаратный набор **14764 пакета прошёл**. Это практически паритет; повторы CPU и неопределённость частоты приведены в документе 26.

Следующий конкретный кандидат — убрать лишнее чтение четырёх карт, затем измерить экономию BRAM и изменение частоты. История [исследования частоты](docs/24%20Ограничения%20частоты%20фиксированной%20сетки.md) сохранена. [Программируемый GRD2](docs/23%20Программируемое%20поле%20и%20цена%20графа.md) отложен по указанию пользователя; аппаратного результата GRD2 нет.

[Обычный C и NEON для тепловой сетки](docs/21%20Тепловая%20сетка%20против%20C%20и%20NEON.md): `make сравнить-сетку`, либо `make сравнить-сетку-плату` с чтением частоты малого ядра. На 128×128 получено около 34 мкс/шаг у одного потока M1 против условных 64 мкс четырёхтрактового кандидата.

Методика и результаты: [новое сравнение с Apple M1](docs/18%20Аппаратный%20опыт%20автономного%20ядра.md) и [первое сравнение](docs/12%20Сравнение%20с%20Apple%20M1.md).

Разбор ограничений функционального образца и план независимого тактирования: [тактирование и вычислительный тракт](docs/13%20Тактирование%20и%20ограничения%20первого%20образца.md).

```sh
make doctor
make lint
make sim
make модели
make bitstream
make sim-синтез
make сравнить         # C на Mac; без измеренной частоты нового ядра — только его число тактов
```

После подключения платы: `make probe`, затем при явном разрешении `ALLOW_FPGA_PROGRAM=YES make program`, `make проверить-плату`, `make проверить-интеграторы`, `make проверить-автономность`, `make сравнить-плату`. Полный набор ошибок и повторных запусков: `.venv/bin/python scripts/dpu.py плата --полная-проверка`.

Прошивка выдаётся после проверки временных ограничений, обработки известной ошибки управления DSP и проверки всех маршрутов входных данных DSP. `make program` дополнительно проверяет её контрольную сумму и свидетельство сборки. Сырые результаты Apio для программирования не использовать. Новое сравнение сохраняется отдельно от первого опыта.

`Makefile` управляет сборкой; PlatformIO вызывает те же действия, например `pio run -e fpga -t fpga-doctor`. Основная цепочка сборки PL — openXC7 через Apio. Vivado подключается дополнительно локально или через SSH; настройки приведены в `.env.example`.


Отдельная [проверка STM32N6](docs/27%20Тепловая%20сетка%20на%20STM32N6.md): **460 аппаратных сравнений скалярного C и Helium прошли**. C + CMSIS, прямые регистры без HAL; при номинальных 800 МГц и рабочей памяти DTCM — **879.994 и 291.458 мкс/шаг**, около трёхкратного ускорения от Helium. По оценке реальной частоты Helium около 293 мкс. Сохранённая база FPGA/M1 не изменена.
